## Logline（选定）

**一个漫画风格的虚拟主播，每天早上用 30–60 秒播报加密市场晨况——价格、涨跌、一条要闻。全片 AI 动画生成，数据层由代码叠加。**

## 为什么是它（选定理由）

1. **职业强相关**（HashKey OTC）——素材、判断力、对「什么算好晨报」的品味自带
2. **「每天」的节奏是整条阶梯的载体**：主播每天必须是同一个人（L3 一致性变硬需求）、每天产出（L4 管线变硬需求）、每天挑片（L5 筛选有真实数据）
3. **漫画风格本身就是规避设计**——绕开真人脸/解剖崩溃维度，与《丧尸清道夫》的机器人脸同构。这是 L2 的思路在选题层就用上了

## 五问否决表

| # | 问 | 答 | 处置 |
|---|---|---|---|
| 1 | 真人脸主角？ | **否** | 漫画风格虚拟主播。character sheet 里要写死「杜绝写实化」——防模型把漫画脸往真人方向磨 |
| 2 | 手部特写？ | 否 | ❓构图腰部以上，手出画或简化为漫画手 |
| 3 | **画面内文字？** | ⚠️ **命中** | 晨报天然要价格/百分比/币种名，而模型生成文字=乱码（破绽 #8）。**绕法（chosen）：所有数字与文字一律 overlay 层**——代码渲染（Remotion / ffmpeg drawtext），视频模型只生成不带文字的画面。这正是「overlays 不进景深轴」规则的实战版 |
| 4 | 背景群演？ | 否 | ❓单主播 + 演播室或城市天际线背景 |
| 5 | 镜面反射？ | 否 | ❓演播室设定避开镜面 |

## 数据真实性红线（本题材特有，与 AGENTS §1 同源）

**价格、涨跌幅等事实数据绝不由模型生成**——由代码从行情 API 取数后叠加。模型负责画面，代码负责事实。
