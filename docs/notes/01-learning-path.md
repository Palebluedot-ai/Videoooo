## 一、最重要的一句话

**《丧尸清道夫》是一个中专生、3 个月经验、10 天、3000 块做出来的。**

所以你的 M5 Max 128G 和「不怕花钱」，在做出精品这件事上**都不是优势**。
瓶颈是**方法**和**镜头量**，不是算力和预算。

> 这句话是本次调研对「别走弯路」最直接的回答。把钱和硬件当杠杆，就是第一个弯路。

## 二、弯路清单（每条都有出处，见 00 / 02 号笔记）

| # | 弯路 | 为什么 | 正解 |
|---|---|---|---|
| 1 | **先学完再做** | 作者 2 月接触 AI，5 月成片爆红 | **作品驱动**：从第一天就在做片子，学习是副产品 |
| 2 | 写「电影感 / 4K / 高细节」 | AI 锚不住空泛词 | 写**具体摄影机型号**：`IMAX胶片摄影机 + Panavision C系列 35mm f4` |

| 9 | **把 Mx-Shell 原始提示词拷进本仓** | 版权归他；**本仓是 public** | 引用链接，别 vendor |
| 10 | 结尾堆特效 | 「没有台词。没有爆炸。没有光芒万丈。」 | **结尾留白** |

## 三、路径：四步，每步一个可交付的片子

> 原则：**每一步都产出一条能看的片子**，不做纯练习。学习是做片子的副产品。

### P1 · 复刻一个镜头（1–2 天）
把《丧尸清道夫》里你最喜欢的**一个镜头**，用五段式重写提示词，自己做出来。

**验证**：
- [ ] 提示词五段齐全，第③段有具体摄影机型号，第④段有呼吸行，第⑤段按秒或按镜切片
- [ ] 抽到一条自己认可的；**记下抽了几次**
- [ ] 写下「我原以为 X，实际是 Y」≥1 条

> 这一步**不写代码**。目的是先有手感——不知道抽卡是什么感觉，写出来的管线全是想当然。

### P2 · 上代码：把手工变管线（3–5 天）
Seedance 走 API（HK 用 **BytePlus ModelArk**，国内版是火山方舟）。

**验证**：
- [ ] `uv run python experiments/e01-seedance/run.py` 从 `shots.yaml` 批量出片，贴完整输出
- [ ] **先 `print(resp)` 原样 dump 真实响应**再写解析（官方文档 JS 渲染抓不到，别照记忆写 SDK 签名）
- [ ] 轮询 + 超时 + 失败重试写对（视频生成是异步任务，不是同步返回）
- [ ] 每条产出自动落台账：prompt / 参数 / seed / 耗时 / 花费 / 文件路径
- [ ] 装上 `/shortfilm-prompt` skill 并实际用它生成一次提示词

### P3 · 做一部完整短片（2–4 周，主线）
目标 **60–90 秒**（不是 3 分半——先收敛再放大）。

**验证**：
- [ ] 角色设定在**设计层**就规避了一致性问题（写下你的「机器人脸」是什么）
- [ ] ≥20 个镜头，生成量 ≥100 条，全部有台账
- [ ] 一条命令从 `shots.yaml` 到粗剪成片（ffmpeg concat）
- [ ] 交付前跑一遍 02 号笔记第六节的自检表
- [ ] 结尾是留白的

### P4 · 可控性攻坚（本地上场）
出现「Seedance 给不了我要的控制」的具体需求时——**且只在那时**——上本地 ComfyUI + Wan。

**验证**：
- [ ] 写清**具体是哪个控制需求**逼你下本地（首尾帧精确？ControlNet 结构？LoRA 特定风格？）
- [ ] 本地跑通一条，记录：模型文件、量化版本、耗时、内存峰值
- [ ] 用 `comfy-mcp` 让 Claude Code 驱动 workflow JSON，不手点 GUI

## 四、云 vs 本地：不是二选一，是分工

### 出片主力 = Seedance（云）
**理由是一条硬能力，不是习惯**：Seedance 2.0 的杀手锏是**音画同步生成**（原生同期音）。
《丧尸清道夫》**80–90% 由「沉浸式短片」模式完成，该模式最重要的能力就是音画同步**。
→ 这个能力**本地开源模型给不了**。你在本地跑 Wan，拿到的是无声画面，音轨还得另外做——直接丢掉这部片子成功的核心。

⚠️ 但注意（repo 表格）：**Seedance 在豆包 App 里被锁死 5/10 秒预设，完整 4–15 秒只在即梦/Dreamina 网页版**。走 API 前先确认你要的时长档位拿不拿得到。

### 本地 128GB = 可控性实验场 + 无限次免费试错
你的机器**能跑**——但先看清代价。已知实测（[papayabytes 指南](https://papayabytes.substack.com/p/guide-comfyui-and-wan-22-image-to)，作者 **M2 Max 64GB**，比你弱）：
- 模型：`Wan2.2-I2V-A14B-HighNoise-Q5_K_M.gguf` + `LowNoise` 两个 GGUF
- **默认 Diffusion 节点不兼容，必须装自定义节点换 GGUF**
- 出黑屏 → 把分辨率从 640×640 降到 **320×320** 才好
- 内存溢出 → 调 `PYTORCH_MPS_HIGH_WATERMARK_RATIO`
- 存储 **50GB 起步**
- 作者原话「step away for a bit and let your laptop get really hot」，**没公布耗时数字**

**诚实的空白**：
- 你是 **M5 Max 128GB**，比这份实测强一档，但**全网没有 M5 Max 的视频生成实测数据**（芯片太新）
- 有源称「Mochi / CogVideoX / Wan2.1 在 Apple Silicon 上根本没支持」，但上面这份 Wan **2.2** 实测成功——**说法互相矛盾，以你自己跑出来的为准**
- 另有源称 Apple Silicon 视频生成比 RTX 4090 慢 **3–4 倍**

→ **结论：本地是 P4 的事，不是 P1。** 别让装环境吃掉你做片子的头两周。

## 五、Claude Code 在这条路上的三个确切位置

| 位置 | 干什么 | 工具 |
|---|---|---|
| **提示词** | 把创意变成合规的五段式多镜提示词 | [`/shortfilm-prompt` skill](https://github.com/jnMetaCode/ai-shortfilm-prompts)（359★，MIT，08-18 还在更新） |
| **管线** | 批量调 API、轮询、重试、台账、失败重投、ffmpeg 拼接抽帧对轨 | 你自己写（这是你「学写代码」的正主） |
| **素材管理** | 一部 3 分钟片 ≈ 200 镜头 × 5–10 倍生成量 = **1000+ 文件**。命名、归档、按镜头分组、挑片记录 | 你自己写 |

**它不干什么**：替你决定哪条好看。**创作决策层不是它的主场**（00 号笔记第四节）。

## 六、三条贯穿纪律

1. **每条生成都记台账**：prompt / 模型 / 参数 / seed / 抽了第几次 / 花了多少 / 选没选中。
   *「选没选中」这一列是金矿——攒够了就能训练自动筛选，而这正是全网空白（00 号笔记第四节缺口）。*
2. **先 dump 再解析**：BytePlus 官方文档是 JS 渲染的，**我抓不到，你也别让 AI 凭记忆写 SDK 调用**。
3. **别 vendor 版权素材**：本仓 public，Mx-Shell 原始提示词版权归他。
