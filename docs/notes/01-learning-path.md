## 零、先纠正一个可能的弯路

你问「是不是 Claude 完全没用、Cursor 完全没用」。答案是**有用，但它不在你可能以为的地方**。

一个有用的类比（**这是我的类比，不是引文**）：

| 编程领域 | AI 视频对应物 | 谁来做 |
|---|---|---|
| prompt engineering | 五槽公式 + 受控运镜/构图词表 | **你**（人的审美与意图） |
| context engineering | 参考图条件化（ingredients）、逐字重复角色描述 | **你** 定策略，**Claude** 批量执行 |
| harness | ComfyUI workflow JSON、comfy-mcp 39 个工具、FLORA MCP | **Claude** 主场 |
| graph engineering | 节点图（ComfyUI / FLORA canvas） | 你搭结构，**Claude** 参数化与派发 |
| eval / 回归测试 | 批量生成后的自动打分筛选 | ⚠️ **本轮零命中，缺口** |

**最容易走的弯路**：以为 Claude 能帮你「出好片」。它不能——**创作决策层不是它的主场**。它的主场是：把你手工点 20 次的事变成一条命令，把工作流 JSON 变成可版本化的代码，把字幕/配音/时间轴自动化。

**第二容易走的弯路**：一上来就下本地跑开源模型。Comfy 官方文档倾向建议 Mac 用户走云端连接（原文见 00-landscape §六）。注意：「官方建议走云」**≠**「本地路线不可行」——后者被 3 票全否。但**本轮没有任何 Apple Silicon 实测数据点**，所以这条路是**未知**，不是「不行」，别在第一阶段就赌它。

## 一、阶段划分（每阶段都有可机械判定的验证标准）

### S0.1 · 手感（不写一行代码）
**目标**：先知道「抽卡」到底是什么感觉，否则后面所有自动化都是空中楼阁。

- 挑**一家**云平台，用五槽公式写 10 条 prompt，每条生成 1 次
- 同一条 prompt 重复生成 5 次，**亲眼看方差有多大**
- 试一次 i2v：先出一张图，再拿它当首帧
- 试一次首尾帧（注意：Veo 该路径**可能要求 8s**，4s 会报 not supported）

**验证标准**：
- [ ] 能说清「同一 prompt 抽 5 次，哪些元素稳定、哪些每次都变」——写进笔记
- [ ] 手上有一条自己觉得能用的片段 + 四条废片，且**说得出废在哪**
- [ ] 记下实际花了多少钱（本轮调研**没有**可信的单价数字，你自己的账单就是第一手数据）

> ⚠️ 第一次跑：最短 prompt、最低分辨率、最短时长。**把链路跑通比把画面跑好重要十倍。**
> ⚠️ **一个 clip 只给一个运镜**（叠加 dolly + pan + tilt 不稳定，Veo 会静默降权运镜指令）。

### S0.2 · 控制（开始写代码，但只写调用）
**目标**：从 GUI 点按钮，转成 Python 调 API。这是你「学写代码」的真正起点。

- 用 Python 调一次视频生成 API，**先 `print(resp)` 原样打出真实响应**再写解析（AGENTS 里的集成探针纪律）
- 把「提交任务 → 轮询 → 拿 URL」写对，含超时（视频生成基本都是异步，不是同步返回）
- 固定 seed 跑两次，验证是否真的可复现
- 把 10 条 prompt 写成结构化文件（YAML/JSON），一条命令批量跑

**验证标准**：
- [ ] `uv run python experiments/e02-batch/run.py` 一条命令产出 10 条视频，贴完整输出
- [ ] 同 seed 同输入跑两次，**用 ffmpeg 逐帧 hash 或文件 md5 验证是否确定性**——贴结果（不管结论是「一致」还是「不一致」，都是真发现）
- [ ] 花费记录进笔记

> 这一步 **Claude Code 是主力**：写轮询、写重试、写批量、写错误处理，正是它擅长的。

### S0.3 · 一致性（方法论真正开始）
**目标**：解决「第二个镜头里的人不是同一个人」。

- 用参考图条件化（ingredients）跑一组 3 镜头的连续画面
- **每条 prompt 逐字重复角色描述**（Generative-Media-Skills 写死的反漂移手法）
- 对比：只靠 prompt 描述 vs 参考图条件化，一致性差多少

**验证标准**：
- [ ] 一组 ≥3 个镜头的片段，同一角色可辨认——**贴首帧截图对比**
- [ ] 笔记里有一条「我原以为 X，实际是 Y」

### S0.4 · 编排（Claude 的主场）
**目标**：把手工流程变成可复现的管线。三选一，看 S0.1–0.3 的实感往哪边偏：

| 路线 | 起步成本 | Claude 怎么介入 | 适合谁 |
|---|---|---|---|
| **A 云 API 直调** | 只付生成费 | 写管线、批量、轮询、重试 | 想学写代码 ✅ **默认推荐** |
| **B FLORA + MCP** | **$18/席/月起**（免费档无视频模型） | 通过 MCP 调模型与 techniques | 想要可视画布 + 编程助手打通 |
| **C 本地 ComfyUI + comfy-mcp** | 免费但吃硬件 | 39 个工具读/改/校验/派发 workflow JSON | 想要白盒完全控制 |

**验证标准**：
- [ ] 一条命令从 `shots.yaml` 跑到成片（含 ffmpeg concat），贴输出
- [ ] 管线可断点续跑（某镜头失败不用全部重来）

### S0.5 · 筛选（⚠️ 无先例，你要自己造）
**目标**：把「抽 20 次人眼挑 1 条」变成「抽 20 次机器排序、人眼只看 top 3」。

**调研在这里是零命中的**——14 条确认结论里没有任何公开的 curation 实现。这意味着两件事：①没有现成方案可抄 ②**这可能是你最有价值的自研点**。

**验证标准**：
- [ ] 有一个打分脚本，输入 20 条候选，输出排序 + 理由
- [ ] 人工盲测：机器 top 3 里至少有 1 条是你人眼也会选的

## 二、工具选型：我的建议

**S0.1 用云平台点着玩，S0.2 起走 A 路线（云 API 直调）。**

理由（对着你的三条约束）：
1. 你说重点是**学写代码** → A 路线代码密度最高，B 是别人写好的 MCP，C 的门槛在装环境不在写代码
2. 你在 **macOS 本机自用** → C 路线的可行性**本轮完全未知**（官方倾向建议 Mac 走云，但「不可行」的结论被全否），第一阶段别赌
3. 你**不做产品化** → 不需要 FLORA 的协作画布（它是按席位卖的）

**什么时候该重新考虑**：
- 想要可视化搭图、且愿意付 $18/月 → 试 FLORA（**注意 8/31 翻倍额度促销到期**）
- 抽卡账单开始肉疼、或想跑开源模型改权重 → 认真评估 C 路线，**先做 Apple Silicon 实测**（这是待查题 3）

## 四、贯穿全程的三条纪律

1. **每次实验记账**：花了多少钱、抽了多少次、留了几条。本轮调研最大的空洞就是价格——**你自己的账单会比网上任何数字都可信**
2. **参数写进文件不写进脑子**：seed、模型版本、prompt 全部结构化落盘。半年后模型换代，只有文件能告诉你当时到底跑的是什么
3. **先 dump 再解析**：接任何新服务，先把真实响应原样打出来对账。AI 视频各家 API 半年一变，**照记忆里的 SDK 签名写必翻车**
