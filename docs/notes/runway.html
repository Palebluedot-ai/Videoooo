S1–S10 · ¥0 · 零生成
S1定题材把「做精品短片」变成一句能被反驳的话 60–75m
  1. 读 course.html 第 1 课 + 阶梯 2.1 节那张表。只读这两块
  2. 新建 docs/preproduction/brief.md：三个候选题材，各 3 行（主角 / 一句话冲突 / 30–60 秒）
  3. 逐个过五问否决表：真人脸主角？手部特写？画面内文字？背景群演？镜面反射？——「是」的改设计或划掉
  4. 选一个写死 logline + 一行「为什么不选另外两个」；cp templates/study-log.md docs/study-log.md 记第一行
⏱ 30 分钟硬闸：选不出就掷硬币——三个都是你写的，差别没你以为的大。禁止上网找灵感，那是最体面的放弃方式。
🟩grep -c '^## ' docs/preproduction/brief.md ≥ 3
🟨五问全部「否」（或写明绕法）。答不出「否」= 题材没选完
S2验尺子预测 8 个 fixture，再发明你自己的坏例子 60–75m
尺子（分镜校验器）曾有两个静默放行洞，已修。你的任务不是修它，是亲手确认它可信到什么范围——你判断不了工具对不对，但你判断得了「我故意弄坏的那一处，它有没有指名道姓报出来」。
  1. 读 SOP 第三节（5-Aspect 三条硬规则）
  2. 先预测：看 tools/fixtures/ 8 个文件名，在 docs/experiments/gate-audit.md 写下每个会红还是绿、红在哪条
  3. 跑 bash tools/run_fixtures.sh，对照预测，差异 = 认知差，进 study-log
  4. 发明 2 个新坏例子试图骗过它。骗过了 = 找到新洞（修 + 固化成 fixture）；没骗过 = 确认了覆盖
🟩run_fixtures 输出贴进 gate-audit.md
🟨预测差异有记录；2 个自发明例子有结论
S3读报错让门拦你一次，看它说什么 45–60m
  1. 把 docs/preproduction/shots.yaml 的 project 名换成你的题材名
  2. 跑 --strict —— 它必须红（示例镜头还是模板的）
  3. 逐条读报错：每条能不能让你知道改哪里？读不懂的让 Claude 改文案
  4. 删示例镜头，把空行补成你题材第一镜的草稿（允许粗糙，本节只求过非 strict）
🟩非 strict 通过；run_fixtures.sh 仍绿（没弄坏尺子）
🟨每条报错都读懂了
闸 G0尺子可信——run_fixtures 全符 + 自发明坏例子有结论。唯一绝对不能绕的闸。新洞修不好 → 删掉那个检查项并写明「这类错机器抓不到，靠人工」——诚实的空缺好过假绿灯。
S4反推 #1 · 易梯度先写预测卡，再看片 75–90m
  1. 定片源（限时 15 分钟）：一部能逐帧看的真人实拍片。网页片暂停后 , . 单帧步进。不下载不入库——仓里只写时间码和文字
  2. 挑易梯度镜头（5–15 秒，静止或单一运镜），记「片名 + 起止时间码」
  3. 先写预测卡 BS01-predict.md：看片前从七问挑 3 条写死答案（背景相对画框动没动？主体位置变没变？有硬阴影吗？焦点变过吗？有 overlay 吗？慢动作吗？镜头有无微浮动？）
  4. 逐帧验证，每条 ✓/✗，✗ 的写「我为什么会那么以为」
  5. 填 BS01.yaml。lens_distortion 只写「广角拉伸/中性/长焦压缩」、focus_dof 只写「深/浅/变焦点」，都加 ⏸猜测——成片读不出参数，硬填是编
🟩--strict 对 BS01.yaml 退出 0
🟨预测卡命中率才是分数，退出码只证明格式没错
S5反推 #2 · 中梯度主体动还是镜头动 60–75m
  1. 挑一个主体运动 + 运镜同时发生的镜头（最常推错的地方）
  2. 预测卡必含「背景相对画框动没动」（唯一客观答案）
  3. 硬纪律：subject_motion 只写主体，camera.movement 只写镜头，同一件事不许两处都写
  4. 记实际耗时——只记录，不设「必须比上次快」
🟩--strict 退出 0
🟨预测已标；两处分工无重复
S6反推 #3 · 难梯度故意先写错，看它报错，再改对 60–75m
  1. 挑多主体 + 明显景深 + 有字幕/图形的镜头
  2. 第一遍故意把字幕写进 spatial_framing，跑校验器，报错贴 study-log
  3. 改进 scene.overlays，再跑
  4. subject 必须做消歧义（谁是谁怎么区分）
🟩破坏版 EXIT=1 且报的是 overlays 那条；改对后 strict 退出 0
S7盲区提炼做出一份别人写不出来的东西 45–60m
  1. 摊开三张预测卡的所有 ✗
  2. 新建 docs/notes/my-checklist.md：「我反复推错的事 / 证据镜头 / 下次开工前先做什么」，≥3 行每行挂 BS0x
  3. 「先做什么」必须是可执行动作（例：填 camera 前先只看背景边缘 5 秒）
  4. 从此每节开工第一件事：读一遍这张表
🟩表 ≥3 行且每行挂 BS0x
🟨逐条自问：是不是只有做过这三次反推的人才写得出来？套话删掉重写
闸 G1反推可靠——BS01–03 全过 strict，9 条预测命中率有记录，my-checklist ≥3 行。命中率无上升趋势 → 反推法对你无效（它本无实证），直接跳 S8，记一行证据。这比硬练第 4 个镜头值钱。
S8beat map把散镜头挂回结构 60–75m
  1. 读 SOP 第二节（15 分钟）
  2. 填 beat-map.md：Hook / Escalation / Reveal / Landing 各一句话 + 时长 + 对应镜头号
  3. silence_windows 写具体秒数（沉默是设计对象）
  4. 四拍不可能都单独占镜头 → 明写哪一拍由哪一镜兼任、为什么
🟩silence_windows 区块含数字
🟨验收四条自查；四拍映射无孤儿
S9★ L2 纸面：约束清单分水岭的前半 75–90m
为什么在花钱之前：L1 的典型卡点是「以为 prompt 不好，其实选题落在崩溃维度」。不先建立这个概念，第一次生成会把随机性和能力搅成一团，然后归因到自己身上。
  1. 读阶梯 2.1 + L2；看一遍《丧尸清道夫》，只列它没拍什么（真人脸/手/文字/群演/镜面）
  2. 新建 constraints.md，顶部写死免责：百分比来自 2025-03 那批模型，每条都是假设，S14 实测后替换
  3. 填表：题材元素 / 崩溃维度 / 绕法A / 绕法B / chosen / 绑到哪拍——四维全覆盖，每行 ≥2 绕法
  4. 让 Claude 写 check_constraints.py（只查结构）+ 你自己写 2 个 fixture
🟩校验器过 + 2 fixture 各红
🟨「改后拍的是另一件事」测试逐行过——只是措辞变了 = 作废重写
闸 G2L2 纸面——每行过「另一件事」测试。过不了的那行绕法作废重写，不许改判据迁就。某维度题材踩不到 → 写明原因即合法。
S10开闸会话平台实读 + 开户 + 记账 · 仍零生成 · 有硬 block 风险 60–90m
  1. 实读官网（不许凭记忆）：BytePlus ModelArk / 即梦 / LibTV 的注册页与定价页，当天看到的写进 platform-check.md，带链接 + 日期
  2. 走注册。香港手机号/证件卡住 → 立刻停，四要素（What/Where/How/Severity）写下，换下一家
  3. cp .env.example .env 填 key（只进 .env）
  4. 写 budget.md：单镜头止损线 / 单会话上限 / 总预警线（锚：Seedance 2.5 低至 ¥0.4/秒挂牌价；简单镜头 2–3 抽、难镜头 20+）
  5. 从 12 破绽表裁出适用你题材的子集 → qc-tells.md，不适用的写明为什么（必须在生成前做完）
🟩git check-ignore -v .env 有输出；key 非空
🟨至少一家账号可用，或 blocker 四要素已写明
闸 G3开闸（钱）——budget / qc-tells 就位，≥1 家账号可用，且你本人说「开始花钱」（🟥 唯一一处，且只管钱不管质量）。三家全过不去 → 排程停在这里（硬 block 不是你的问题）：回 S4 再反推两镜（不花钱那条路），同时另找平台。

S11★ 第一笔钱：turnaround 出图图，不是视频 · 几块钱 75–90m
为什么绕不过：L0 判据白纸黑字要五视图 + HEX 色标，且它是 L3 的唯一资产源头。要么现在做，要么明确降级并登记解禁点——不许假装 L0 过了。
  1. 先出基准角色图（turnaround prompt 是图生图，没基准图跑不了）
  2. 出 turnaround。只有 turnaround 这个词不能改，整条 prompt 可改——引文那条是 four-panel 不含 3⁄4 视图，与五视图判据冲突：分两次出或改写，改动登记进 phase 卡
  3. 重试上限 3 轮，超了交四视图 + 登记偏离，不许无限重出
  4. 填完 character-sheet 六件套；花费记 budget.md
🟩HEX 色标 ≥4 处
🟨五视图对基准线比头顶/肩/腰/脚；图不入 git（≤200KB 缩略图除外）
S12自己的分镜表 → 撞 L0 闸3–5 镜，≥1 hero 五维全填 75–90m

  2. 每镜加一行 notes：用了 constraints.md 哪条绕法
  3. 开工前读 my-checklist，收工前逐镜对它自查

🟨绕法引用都能找到对应行
闸 G4L0 过关——strict 过 + 模板有 diff + turnaround 五视图交付。turnaround 没做不许标 L0 done：补做，或登记降级 + 写明解禁点（L3 第一件事变成补它）。
S13★ 第一条视频同一 hero 镜头抽 10–15 次 · 大概率拆成 2–3 节 90m 硬停
学习期终点。为什么是这里：四件保护装置齐了——绕开崩溃维度的题材（S1+S9）、生成前裁好的 QC 清单（S10）、止损线（S10）、拦得住的分镜表（S12）。少任何一样，第一次生成测的都是运气而不是能力。
  1. 读五段式方法论第一节，把 hero 镜头翻译成五段式（呼吸感行、声音行必备）
  2. 写调用脚本，放 docs/experiments/ 不放 tools/。铁律：先 print(resp) dump 真实响应再写解析
  3. 抽 10–15 次（抽卡方差本身就是 L1 要学的东西，抽 3 次省的钱让你什么都学不到）
  4. L1-log.md 每行：日期/prompt版本/model/参数/seed/第几抽/花费/命中哪几条 tell/选没选中——最后这列是 L5 的训练数据，不许省
🟩台账 ≥10 行且「选没选中」无空值；总花费 ≤ budget 上限
🟨每抽对 qc-tells 逐条判定
闸 G5L1 过关——最好那条在适用 tell 上 0 命中。15 抽无一条 0 命中 → 先查是否踩崩溃维度（对 constraints.md）。是 → 跳 S14 改设计；不是 → 改 prompt 最多 2 次，第 3 次仍败就记认知差、L1 标 todo、带着问题走 S14。
S14★ L2 实证A/B：把假设换成实测数字 · ¥40 量级 90m
  1. 从 constraints.md 挑一条绕法做 A/B：A=硬扛版，B=绕开版，其余参数一致
  2. 先写判定线再跑（写进 constraints.md）：B 命中率 ≤ A 的一半 → 成立；4:6~6:4 → 未证实（不是「绕法无效」）
  3. 每臂 10 条；结果写回 verified_by：实测命中率 + 日期 + 模型版本
🟩预注册检查：判定线的 commit 必须早于素材（git log 可查）
🟨结论三选一已写。「未证实」是合法结论，不许改判定线去凑
S15结账复述、状态面、下一级入口 60m
  1. 写 08-my-L2.md：只写 S14 实测出来的，没验过的标 ⏸
  2. 主会话更新 progress.yaml：L0/L1/L2 真实状态，没到判据老实标 todo
  3. phase 卡补台账，偏离登记齐；方法论心得进想法箱等「agent-on 结账」
🟨「能教会别人」可操作版：把 08-my-L2.md 丢给空白会话，让它只读这份文件对新题材产出约束清单，你逐条挑它的错——测的是你挑得出错
闸 G6L2 分水岭——预注册过 + 结论三选一已写 + 挑错测试挑出 ≥1 真错。「未证实」不是失败；「反向」（B 更差）是最有价值的产出，重点写。

防停滞六条（全是可执行动作）

  1. 每节以绿收尾——手段可以是删掉填不完的半成品镜头让它过。红色过夜是不回来的头号原因
  2. 关电脑前写下一句祈使句进 study-log 末行，必须含文件名和命令。回来时不用重新决策
  3. 15 分钟降梯度：卡满 15 分钟无可验证进展 → 降难度或砍元素，记认知差继续。禁止「先把资料研究清楚再动手」
  4. 90 分钟无条件硬停。S13 尤其：「再抽一次说不定就好」是烧钱和烧热情的同一个机制
  5. 每节一个 commit（sN: 产出物名）。连续两周无 commit = 排程已停，不是「最近有点忙」
  6. 断更超 7 天的回归动作：不重读文档——跑 run_fixtures.sh + 读 study-log 最后那句祈使句，从它开始

两条禁令：搜教程 / 比较课程 / 收藏链接 = 停滞的第一信号（这个领域没有教科书）；progress.yaml 只有主会话写。

已知弱点（九条，完整版在仓里 07 号笔记）：反推法无实证（G1 有 kill switch，但 S4–S7 的 4–5 小时风险只是可见没有消除）· fixture 只覆盖想得到的错法 · S13 时间成本是估计（BytePlus SDK 至今未验证）· S10 有真硬 block 风险（香港实名，无第一手数据）· S14 n=10/臂只能看数量级 · 「能教会别人」是最弱的闸 · 对低频节奏（两周一次）没有适配 · L3 之后有意没排 · 最根本：L0–L6 划分本身是自建的，若它错了，这份排程会把你非常精确地送到一个错误的地方——唯一对冲是 study-log 里的认知差，那是唯一不依赖划分对错的产出。
