## 一、三条组织原则

1. **先验尺子，再量东西。** 绿灯只在被 fixture 覆盖的范围内可信。
2. **判据分三档，必须标明是哪一档**（见下）。把结构检查冒充能力判据，是三份候选方案共同的崩点。
3. **每节以一条绿命令收尾，并留下一句下次的开工祈使句。** 红色状态过夜是不回来的头号原因。

## 二、判据三档（本排程的认识论）

| 档 | 记号 | 能测什么 | **测不到什么** |
|---|---|---|---|
| 机器判据（退出码） | 🟩 | 字段齐不齐、顺序对不对、文件在不在 | **内容对不对**。格式完美的胡话可以 100% 通过 |
| 有客观答案的人工判据 | 🟨 | 预测命中率、逐帧对照 | 需要你亲自看一眼 |
| 自评 | 🟥 | 你的感觉 | 几乎必然高估。**没有任何一道闸单独靠 🟥** |

**铁律**：只有 🟩 过而 🟨 没做，这一节就没做完。
**反向铁律**：🟩 报错时先问「是它对还是我对」——尺子会坏，上面刚证明过。

## 三、时间（诚实版）

- 标称 15 节 × 45–90 分钟 ≈ **17–20 小时**；**真实预算 28–35 小时**（第一次做的活取上限；S13 大概率溢出成 2–3 节）
- 每周 2–3 次 → **6–10 周**
- **超时不叫失败**，拆节续做即可。真正的失效信号是**连续两周没有新 commit**

**S1 · 定题材：把「做一部精品短片」变成一句能被反驳的话** · 60–75 min

> 处置的卡点：requirements 只写了「做精品短片」，**题材从来没人定过**——beat map / 设定集 / 分镜全在消费一个不存在的输入。

1. 读 `course.html` 第 1 课 + `04` 第 2.1 节那张表。**只读这两块**
2. 新建 `docs/preproduction/brief.md`：**三个**候选题材，每个 3 行（主角 / 一句话冲突 / 时长 30–60 秒）
3. 逐个过**五问否决表**：有真人脸主角？手部特写？画面内文字？背景群演？镜面反射？——答「是」的要么改设计要么划掉
4. 选定一个，顶部写死 logline + 一行「为什么不选另外两个」
5. `cp templates/study-log.md docs/study-log.md`，记第一行

验证：🟩 `test -f docs/preproduction/brief.md && grep -c '^## ' docs/preproduction/brief.md` ≥ 3 · 🟨 五问全「否」（或写明绕法）

> ⏱ **30 分钟硬闸**：选不出就掷硬币——三个都是你写的，差别没你以为的大。**禁止上网找灵感**，那是最体面的放弃方式。

**S2 · 验尺子：预测 8 个 fixture，再发明你自己的坏例子** · 60–75 min

> 尺子已修好（见第零节），你的任务不是修它，是**亲手确认它可信到什么范围**。

1. 读 `05` **第三节**（5-Aspect 三条硬规则）
2. **先预测**：打开 `tools/fixtures/` 看 8 个文件名，在 `docs/experiments/gate-audit.md` 写下你认为每个会红还是绿、红在哪条
3. 跑 `bash tools/run_fixtures.sh`，对照预测，差异写成认知差进 study-log
4. **发明 2 个新坏例子**（想一种你觉得能骗过它的写法），实测。骗过了 = 你找到了尺子的新洞（记认知差，让 Claude 修 + 固化成 fixture）；没骗过 = 你确认了覆盖

验证：🟩 `run_fixtures.sh` 输出贴进 gate-audit.md · 🟨 预测与实测的差异有记录 · 🟨 2 个自发明例子有结论

**S3 · 读报错：让门拦你一次，看它说什么** · 45–60 min

1. 把 `docs/preproduction/shots.yaml` 的 project 名换成你 S1 定的题材名（其余先不动）
2. 跑 `uv run --with pyyaml tools/check_shotlist.py --strict docs/preproduction/shots.yaml`——**它必须红**（示例镜头还是模板的）
3. **逐条读报错**：每条能不能让你知道下一步改哪里？读不懂的报错记下来让 Claude 改报错文案（报错是给人读的）
4. 删掉 S01 示例镜头，把 S02 空行补成你题材的第一个镜头的**草稿**（允许粗糙，本节只求过非 strict）

验证：🟩 非 strict 跑通过（警告允许）· 🟩 `bash tools/run_fixtures.sh` 仍绿（改动没弄坏尺子）· 🟨 每条报错都读懂了

**S4 · 反推 #1（易梯度）：先写预测卡，再看片** · 75–90 min

> 处置的卡点：反推法有一半**没有标准答案**（成片里读不出焦段和光圈）；片源有版权红线。

1. **定片源**（限时 15 分钟）：一部你能逐帧看的**真人实拍**片。本地文件用 QuickTime/IINA 逐帧；网页片暂停后 `,` `.` 单帧步进。**不下载、不入库**——仓里只写时间码和文字
2. 挑一个**易梯度**镜头（5–15 秒，静止或单一运镜），记 `片名 + 起止时间码`
3. **先写预测卡** `docs/preproduction/backsolve/BS01-predict.md`——看片前从这七问挑 3 条写死答案：背景相对画框动没动？主体画框位置变没变？有硬阴影吗？焦点变过吗？有 overlay 吗？是慢动作吗？镜头有无不规则微浮动？
4. 逐帧验证，每条 ✓/✗，✗ 的写「我为什么会那么以为」
5. 填 `BS01.yaml`。**`lens_distortion` 只写「广角拉伸/中性/长焦压缩」，`focus_dof` 只写「深/浅/变焦点」，后面都加 `⏸猜测`**——成片读不出参数，硬填是编

验证：🟩 `--strict` 对 BS01.yaml 退出 0 · 🟨 **预测卡命中率才是分数**，退出码只证明格式没错

---

**S5 · 反推 #2（中梯度）：主体动还是镜头动** · 60–75 min

1. 挑一个**主体运动 + 运镜同时发生**的镜头（最常推错的地方）
2. 预测卡**必含**「背景相对画框动没动」（唯一客观答案）
3. 填 `BS02.yaml`，硬纪律：**`subject_motion` 只写主体，`camera.movement` 只写镜头，同一件事不许两处都写**
4. 记实际耗时——**只记录，不设「必须比上次快」**

验证：🟩 `--strict` 退出 0 · 🟨 预测已标 · 🟨 两处分工无重复

---

**S6 · 反推 #3（难梯度）：故意先写错，看它报错，再改对** · 60–75 min

1. 挑**多主体 + 明显景深 + 有字幕/图形**的镜头
2. 第一遍**故意**把字幕写进 `spatial_framing`，跑校验器，报错贴 study-log
3. 改进 `scene.overlays`，再跑
4. `subject` 必须做**消歧义**（谁是谁怎么区分）

验证：🟩 破坏版 `EXIT=1` **且报的是 overlays 那条** · 🟩 改对后 `--strict` 退出 0

**S7 · 盲区提炼：做出一份别人写不出来的东西** · 45–60 min

1. 摊开三张预测卡的所有 ✗
2. 新建 `docs/notes/my-checklist.md`：`| 我反复推错的事 | 证据镜头 | 下次开工前先做什么 |`，**≥3 行每行挂 BS0x**
3. 「先做什么」必须是可执行动作（例：填 camera 前先只看背景边缘 5 秒）
4. 从此每节开工第一件事：读一遍这张表

验证：🟩 `grep -cE '^\|.*BS0[1-3]' docs/notes/my-checklist.md` ≥ 3 · 🟨 逐条自问：是不是**只有做过这三次反推的人**才写得出来？套话删掉重写

**S8 · beat map：把散镜头挂回结构** · 60–75 min

**S9 · ★L2 纸面：约束清单（分水岭的前半）** · 75–90 min

> **为什么在花钱之前**：L1 的典型卡点是「以为 prompt 不好，其实选题落在崩溃维度」。不先建立这个概念，第一次生成会把随机性和能力搅成一团，然后归因到自己身上。

1. 读 `04` 第 2.1 节 + L2；**看一遍《丧尸清道夫》，只列它没拍什么**（真人脸/手/文字/群演/镜面）——这是读规避设计
2. 新建 `docs/preproduction/constraints.md`，顶部写死免责：*百分比来自 2025-03 那批模型，每条都是假设，S14 用自己的素材校准后替换*
3. 填表：`| 题材元素 | 崩溃维度（假设）| 绕法A | 绕法B | chosen | 绑到哪拍/哪镜 |`——**四维全覆盖，每行 ≥2 绕法**
4. 让 Claude 写 `tools/check_constraints.py`（只查结构）+ 你自己写 2 个 fixture

验证：🟩 校验器对 constraints.md 退出 0、两个 fixture 各退出 1 · 🟨 **「改后拍的是另一件事」测试**逐行过——只是措辞变了、要拍的还是同一件事 = 作废重写

**S10 · 开闸会话：平台实读 + 开户 + 记账（仍零生成）** · 60–90 min · **有硬 block 风险**

**S14 · ★L2 实证：把假设换成实测数字** · 90 min

4. 结果写回 `verified_by`：实测命中率 + 日期 + 模型版本

验证：🟩 **预注册检查**——判定线的 commit 必须早于素材（`git log -S'判定线'` 对比两文件时间）· 🟨 结论三选一，**「未证实」是合法结论**，不许改判定线去凑

## 六、防停滞（六条，全是可执行动作）

1. **每节以绿收尾**——手段可以是删掉填不完的半成品镜头让它过。红色过夜是不回来的头号原因
2. **关电脑前写下一句祈使句**进 study-log 末行，必须含文件名和命令。回来时不用重新决策
3. **15 分钟降梯度**：卡满 15 分钟无可验证进展 → 降难度或砍元素，记认知差继续。禁止「先把资料研究清楚再动手」
4. **90 分钟无条件硬停**。S13 尤其：「再抽一次说不定就好」是烧钱和烧热情的同一个机制
5. **每节一个 commit**（`sN: 产出物名`）。**连续两周无 commit = 排程已停**，不是「最近有点忙」
6. **断更超 7 天的回归动作**：不重读文档，只做两件事——跑 `run_fixtures.sh` + 读 study-log 最后那句祈使句，从它开始

**两条禁令**：搜教程/比较课程/收藏链接 = 停滞的第一信号（这个领域没有教科书）；`progress.yaml` 只有主会话写。

## 八、已知弱点（诚实版）

1. **反推法无实证**。G1 装了 kill switch（预测命中率无上升 → 跳过），但若 S4–S7 白花，4–5 小时的风险没消除，只是可见
2. **fixture 只覆盖想得到的错法**。「机器判据优先」的正确读法：只在 fixture 覆盖的范围内优先
3. **S13 时间成本是估计**：BytePlus model ID / SDK 至今未验证（文档 JS 渲染抓不到），90 分钟大概率不够
4. **S10 有真硬 block 风险**：香港身份实名，无第一手数据，三家全挂则 S11 后悬空
5. **S14 n=10/臂不够统计推断**，只能看数量级；落在 4:6~6:4 就是花 ¥40 没证明什么
6. **「能教会别人」是最弱的闸**：AI 恰好写对时你挑不出错，闸无信号
7. **对低频节奏（两周一次）没有适配**：S4–S7 手感会断
8. **L3 之后有意没排**：L3 第一件事是验「turnaround 优于单图」这个无实证推论，没素材前排 L3 = 凭空规划
9. **最根本**：本排程建立在 04/05/06 三份自建笔记上，L0–L6 划分若错，它会把你**非常精确地送到一个错误的地方**。唯一对冲是 study-log 的认知差——那是唯一不依赖划分对错的产出
